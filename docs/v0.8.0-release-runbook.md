# v0.8.0 Release Runbook

Use this runbook for the v0.8.0 enterprise Portal access release.

## Preflight

```bash
git status --short
npm ci
npm run build
npm run test:all
git diff --check
```

`npm run test:all` covers:

- public default mode
- hosted MCP auth
- missing/bad token and insufficient scope
- tenant and endpoint cache isolation
- readiness checks
- HTTP artifact smoke
- package contents

## HTTP Artifact Smoke

The local artifact smoke is part of `npm run test:http-runtime`. It starts `dist/http.js` and verifies:

- public `/health`
- public `/ready`
- public `/tools`
- MCP `initialize`
- MCP `tools/list`
- MCP `resources/read` for `sqd://tools`
- protected MCP POST auth
- protected `/metrics`
- representative live tools
- safe JSON observability fields

Run it directly after `npm run build`:

```bash
npm run test:http-runtime
```

## Docker Smoke

Build and run the image:

```bash
docker build -t sqd-portal-mcp:v0.8.0 .
docker run --rm -p 3000:3000 \
  -e MCP_HTTP_BEARER_TOKEN=test-mcp-token \
  -e MCP_CURSOR_SECRET=test-cursor-secret \
  -e METRICS_BEARER_TOKEN=test-metrics-token \
  sqd-portal-mcp:v0.8.0
```

Smoke the public and protected endpoints:

```bash
curl -fsS http://localhost:3000/health
curl -fsS http://localhost:3000/ready
curl -fsS http://localhost:3000/tools | jq '.tool_count'
curl -fsS http://localhost:3000/metrics -H "Authorization: Bearer test-metrics-token" | head
curl -sS http://localhost:3000/mcp \
  -H "Authorization: Bearer test-mcp-token" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  --data '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

## Dynamic Dedicated Portal Smoke

For production same-origin dedicated portals, prefer dynamic `*.portal.sqd.dev` routing instead of enumerating customer hostnames. Preserve `Host` at the edge; the MCP service derives `portalBaseUrl=https://<customer-slug>.portal.sqd.dev` and uses delegated API-key auth for that host. `https://portal.sqd.dev/mcp` must remain public.

## Hosted Enterprise Smoke

Use a staging endpoint and a staging portal-app issued MCP key:

```bash
PORTAL_ENDPOINTS='[{"id":"staging-enterprise","portalBaseUrl":"https://staging-upstream.portal.example.com","mcpHostnames":["staging.portal.example.com"],"label":"Staging enterprise","endpointClass":"enterprise","tenantScope":"tenant","tenantId":"staging-org","authMode":"bearer","tokenEnv":"STAGING_PORTAL_TOKEN"}]'
PORTAL_DEFAULT_ENDPOINT_ID=staging-enterprise
STAGING_PORTAL_TOKEN=<outbound-portal-token>
MCP_AUTH_KEYS='[{"id":"staging-mcp-key","audience":"portal-mcp","tokenSha256":"<sha256>","principalId":"staging-user","tenantId":"staging-org","endpointId":"staging-enterprise","scopes":["mcp:invoke"],"credentialPolicy":"tenant_portal_endpoint","status":"active"}]'
MCP_READINESS_STRICT=true
MCP_CURSOR_SECRET=<cursor-secret>
METRICS_BEARER_TOKEN=<metrics-token>
```

Verify:

- `/ready` is 200.
- anonymous MCP POST returns JSON-RPC 401.
- bad MCP bearer returns JSON-RPC 401 and does not echo the token.
- insufficient-scope key returns JSON-RPC 403.
- valid hosted key can run `initialize`, `tools/list`, `sqd://tools`, and `portal_get_head`.
- JSON tool events contain endpoint id/class, hashed tenant key, auth outcome, request id, invocation id, and upstream Portal status.
- JSON tool events do not contain raw principal ids, raw tenant ids, key ids, bearer values, or outbound Portal credentials.

## Release

Before tagging, ensure `CHANGELOG.md` has a hand-written `0.8.0` entry. Then run:

```bash
npm run release:minor
```

Push the release commit and tag after reviewing the generated diff:

```bash
git push
git push --tags
```
